# 大阪石材 AIチャットボット・管理画面（試作）

大阪石材（https://www.osaka-sekizai.jp/）のホームページ向けAIチャットボットと、その管理画面のUI/UX試作です。

**現在のスコープ：フェーズ1・2・3・UI/UXのみ。** バックエンドや外部API（Supabase / Anthropic Claude API / Voyage AI）は使用していません。データはすべてブラウザ内の仮データ（`localStorage`）で、AIの回答は「登録されたFAQとの簡易一致」によるダミー応答です。将来の本実装に向けた要件・設計判断・用語ルールは [`CLAUDE.md`](./CLAUDE.md) にまとめています。

## セットアップ

```bash
npm install
npm run dev
```

`http://localhost:3000` を開くと、下記2つの画面へのリンクがあるトップページが表示されます。

## 画面

| URL | 内容 |
| --- | --- |
| `/admin` | 管理画面ホーム（今やること・使い方の3ステップ） |
| `/admin/sources` | 「AIに覚えさせる情報」（URL・PDF・テキストの登録、一覧管理） |
| `/admin/faq` | 「よくある質問」（追加・編集・検索・削除） |
| `/admin/unanswered` | 「答えられなかった質問」（回答を書いてFAQ化／対応しない） |
| `/admin/persona` | 「話し方・ルール」（口調・答えさせない話題・案内先） |
| `/admin/appearance` | 「見た目」（色・位置・アイコン・名前・あいさつ・候補ボタン） |
| `/admin/usage` | 「利用状況」（今月の利用状況・月の利用上限・上限到達時の案内） |
| `/admin/members` | 「メンバー」（招待、権限の一覧・変更・削除） |
| `/admin/publish` | 「公開と履歴」（未公開の変更一覧・公開する・公開履歴・この版に戻す） |
| `/admin/conversations` | 「会話ログ」（お客さま向けチャットの会話を検索・閲覧） |
| `/widget-demo` | お客さま向けチャットの見た目を確認するデモページ（公開版を表示） |

管理画面では常に右側に「テスト画面」が表示され、**下書き**の内容でチャットを試せます。「よくある質問」「話し方・ルール」「見た目」の変更は下書きとして保存され、「公開する」を押すまで `/widget-demo`（お客さま向け）には反映されません。「AIに覚えさせる情報」「メンバー」「利用状況」は保存するとすぐに反映されます（詳しくは `CLAUDE.md` の設計判断を参照）。

## 確認手順

1. `npm run dev` でローカルサーバーを起動する。
2. `/admin/faq` で、初期5件のFAQに回答を入力する（初期状態は回答が空欄で「回答が未入力です」と表示される）。保存すると画面右のテスト画面ですぐに回答が返ることを確認する。
3. `/admin/persona` で口調や答えさせない話題を変更し、`/admin/appearance` でテーマ色や候補ボタンを変更する。それぞれ保存すると、右のテスト画面に反映されることを確認する（このときヘッダーの「未公開の変更」件数が増える）。
4. テスト画面で、答えさせない話題に該当する質問（例：「他社と比較してどちらが安いですか」）を送り、丁寧な断り文＋案内先が返ることを確認する。また、FAQにない質問を送り、「答えられなかった質問」に記録されることを確認する（`/admin/unanswered` で確認）。
5. `/admin/unanswered` で「回答を書く」→「よくある質問に追加」を行い、一覧から消えて `/admin/faq` に追加されることを確認する。
6. `/admin/publish` で未公開の変更一覧を確認し、「この内容で公開する」を押す。ヘッダーが「公開中の内容と同じです」に変わり、公開履歴に版が1つ追加されることを確認する。もう一度どこかを変更して公開したあと、古い方の版の「この版に戻す」を押し、内容が戻ることを確認する。
7. `/widget-demo` を開き、公開した内容（色・FAQ回答など）が反映されていることを確認する。
8. `/admin/sources` で、URL・PDF・テキストいずれかの方法で情報を追加し、一覧に「読み込み中…」→「読み込み済み」と表示が変わることを確認する。「チャットで使う」スイッチのON/OFF、削除後の「元に戻す」トーストを確認する。
9. `/admin/members` で自分の権限を「見るだけ」に切り替え、他の画面（よくある質問・見た目など）の追加・編集・削除・保存・公開ボタンが操作できなくなることを確認する。確認後は「編集できる」に戻す。
10. `/admin/usage` で「上限に達した状態を試す」をONにして保存し、テスト画面や `/widget-demo` で質問すると、通常の回答の代わりに案内文だけが返ることを確認する。確認後はOFFに戻す。
11. `/widget-demo` で電話番号やメールアドレスを含む質問を送り、`/admin/conversations` で該当の会話を開くと、それらが伏せて表示されることを確認する（テスト画面での会話はここには表示されません）。

## 今後（本実装）

- `src/lib/data/`（データ取得層）と `src/lib/answer/`（回答生成層）の中身を、Supabase・Claude API・Voyage AI 等の実APIに差し替える。呼び出し側のコンポーネントは変更不要な設計にしている。
- ログイン機能（Supabase Auth）の追加に伴い、`/admin/members` の「動作確認用：自分の権限を切り替える」は削除し、ログイン中のメンバーの権限をそのまま使うようにする。
- 会話ログの保存期間に基づく自動削除、利用状況の実績値への置き換え、レート制限・ドメイン制限などの運用機能はバックエンド実装時に追加する。

## 費用の目安について

本フェーズはUI/UXのみの試作のため、外部APIの利用料は発生しません。本実装フェーズ（Supabase / Claude API 等の導入）に進む際に、利用量に応じた費用目安を別途まとめます。
